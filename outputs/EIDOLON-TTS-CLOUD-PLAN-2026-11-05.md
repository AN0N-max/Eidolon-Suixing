# Eidolon 随行：云端 TTS 开发计划

日期：2026-11-05。状态：第一批模拟开发版0.1.0.dev2已实现并在本机验证，默认关闭、未部署。步骤1已交付探测脚本但尚未在实际服务器运行；步骤2/3完成持久状态和HTTPX进程内假上游，真实网络上游、私密配置与手机接入仍待完成。完整89项离线检查及安装wheel后的回环HTTP/真实本机断线验证通过；没有真实Fish请求。此方案取代此前“首期 TTS 固定留在手机端，因此必须兼容速云与另一个 VPN 同时运行”的前提。

## 目标和当前基线

将 Fish TTS 请求与其需要的网络出口环境放在自己的服务器。手机只需访问私网后端并播放音频，随行 TTS 不再依赖手机速云；这不代表会修改用户其他应用的代理配置。

目标链路：手机原生语音入口 → 私网 HTTPS → 云端 TTS 中转 → 服务器指定出口 → Fish Audio；PCM 音频流沿原路返回，由现有 VoicePlayer/PcmSpool/AudioTrack 播放。

- 实际 Android：1.28.1/code85，Java 原生层 + WebView，min26/target35，SQLite/加密备份 v18。
- 云端：自编 FastAPI/SQLite 框架 0.1.0.dev1。用户截图已确认运维工具 2026.11.05.1 接管 systemd、运行/健康/认证检查与在线备份成功。已启用开机启动，但尚未做服务器重启恢复或真实恢复验收。
- 当前 FishClient 直接从手机调用 https://api.fish.audio/v1/tts；现有请求为 JSON，PCM/44100Hz，模型与角色音色沿用当前配置。Fish 官方接口资料支持 JSON、PCM/44.1kHz/16-bit/mono，实施时按既有参数核对，不顺带更换模型或声音。
- 当前 VoicePlayer 已支持边接收边播放、暂停、取消和本机缓存；PcmSpool 单条上限16MiB。CallService 仍检查手机 Fish 密钥，VoiceCache 标识也引用该密钥，这两处需要适配。
- 完整角色云端托管仍未接入。TTS 中转可先独立完成，不需要先迁移聊天、关系、记忆、日程或 ASR。

## 分阶段开发与交付

| 步骤 | 要做的工作 | 交付物与通过条件 | 开发量估算 |
|---|---|---|---|
| 1. 服务器出口预检 | 明确 Fish 的直连/专用代理配置；验证 DNS、TCP、TLS；制作检查脚本，不调用合成接口、不带密钥 | 分阶段报告实际可达性与错误；不拿域名能解析或端口能连接冒充真实合成通过 | 0.5–1日 |
| 2. 明确请求与完成协议 | 定义设备认证、稳定请求ID、文本/音色/模型白名单、状态/取消/完成校验；设计持久请求登记与兼容迁移 | 接口和状态说明、故障矩阵；重试策略不会重复发起未知结果的付费请求 | 1–2日 |
| 3. 后端模拟中转 | 使用 FastAPI + HTTPX 异步流式传输；假上游分块返回人工 PCM；限流、并发、大小、超时与断线取消 | 不用真实密钥即可验证音频流、回压、错误、取消和请求去重；服务进程重启不自动重发 | 2–3日 |
| 4. 手机增量接入 | 新增云端 TTS 传输适配和集中设置；沿用现有播放器、缓存、音色、双语取词与 CallEpoch 等保护 | 原签名测试 APK；朗读与通话均可通过假上游播放，旧缓存可使用，通话不再强制要求手机 Fish 密钥 | 2–3日 |
| 5. 私网与手机流量 | 使用单一 WireGuard 私网连接；限定服务器入口与设备权限；Caddy HTTPS 与手机信任配对 | 手机不开速云也能收取模拟 TTS；验证 Wi-Fi/流量切换、断网、锁屏、挂断和重连，不开放公网 TTS API | 1–2日 |
| 6. 经授权的真实验证 | 用户在服务器私密配置中填写 Fish 密钥与出口配置；先一条明确短文本，再测有界多轮 | 记录首音、完整播放、错误与费用证据；真实请求需授权，不自动重试、不以余额猜成功 | 0.5–1日，等待另计 |
| 7. 回归与发布 | 原聊天/语音/取消/备份/角标等必要回归；更新公告、功能说明、源码、脚本、APK与交接 | 原签名覆盖升级、保留旧数据/旧APK，清楚列出实际通过和未验证范围，可手动回退模式 | 1–2日 |

总计约8–14个有效开发日，属于工作量估算，不是固定日期承诺；证书/网络环境与真机等待另计。出口预检和本地假上游开发可交叉进行。第一批优先交付步骤1–3，先有不付费的可验证中转，再改手机。

## 责任边界与配置

服务器保存 Fish 密钥、可用的出口配置、允许的模型/音色、并发与预算限制。代理优先采用可明确配置的 HTTP CONNECT 出口；若环境只有 SOCKS 再评估相应依赖。不能把 Windows/手机速云客户端直接视为可在 Ubuntu 运行的服务器组件；也不假定杭州服务器能直接访问 Fish。

仅 TTS 上游客户端使用指定代理；本机健康检查、私网入口和其他现有请求不受全局代理变量干扰。保留 TLS 验证，固定受控上游地址，不允许手机传任意 URL、代理地址或服务商密钥，防止变成通用转发器。HTTPX 使用受管理的异步客户端和明确超时，关闭自动重定向及自动重发，退出时关闭流与连接。

密钥与代理凭据保存在服务器受限配置文件，由运维入口加载；不写入公开 service 文件、GitHub、终端回执、设备页面或日志。开发中不要求用户把订阅/节点/密钥发到聊天。现有 service 有严格内容校验，新增配置加载必须设计已知旧版本的可审查迁移，不能要求随意手改 unit 或取消安全限制。

手机保存私网地址、设备令牌与所需的公开信任材料，继续保留当前角色音色、模型选择与本地语音缓存。所有配置集中于现有“设置 → 模型与接口”相关语音入口，不添加另一套散落配置页。旧 Fish 密钥不自动删除或上传，直连模式可作为用户明确选择的回退；云端失败时不得自动切直连再付费请求。

## 接口与持久状态草案

接口命名在编码前锁定，以下为候选：

- POST /api/tts/stream：设备认证后提交稳定 requestId、已清洗的纯台词、音色、模型及受控发音参数，返回 PCM 流与格式元数据。
- GET /api/tts/requests/{requestId}：同设备查询完成状态、实际字节数及摘要；查询本身不发起合成。
- POST /api/tts/requests/{requestId}/cancel：同设备取消；重复取消可安全处理，不返回其他设备的信息。
- 已有健康接口只补充不含凭据的 TTS 配置/可用状态，不能为健康检查自动调用付费合成。完整领域接入状态仍独立，不能因为 TTS 已连通而把 domainConnected 改成 true。

付费前登记请求，状态至少区分：尚未发送、上游已开始、完整接收、明确未发送失败、已取消、结果未知。相同 requestId/相同输入不得重复请求 Fish；相同ID不同输入拒绝。上游开始后连接断开或进程死亡，不能把未知状态当作未请求并自动重试。除非有已核实的服务商幂等能力，不承诺计费恰好一次。

新增持久登记优先作为云端控制数据库的增量表，编码前单列 schema 迁移；当前运维脚本只接受 schema1 和原表白名单，必须同步升级其备份/校验/恢复兼容性，不能加表后把运维工具弄坏。原手机数据库不为中转无故升级；确有新持久字段时再设计增量迁移和 v18 备份兼容，不把回执随意塞进业务消息。

首次只允许每设备一条活动 TTS，服务端总并发从1开始测量。文本沿用当前5000字与音色格式校验，另限请求字节/发音字典大小；音频沿用16MiB边界。连接、读取空闲与整请求截止分别限制，具体值依据现有20秒连接/60秒读取边界与实际测试确定，不把一条音频无限排队。

## 音频完成、播放和取消

音频保持当前 PCM 格式与播放器约定。边接收边播放，默认服务器不长期落盘音频或正文；手机仍沿用已有缓存与临时文件管理。请求登记只保留必要状态、输入摘要、设备与完成校验，不记录完整私聊、原始输入录音或密钥。

关键规则：不能因为 HTTP 流结束就判为完整音频。转发中断可能恰好落在完整采样边界，因此必须结合服务端“上游完整结束”的持久状态、接收字节数/摘要验证。候选方式是在手机完成流接收后查询请求结果，校验成功才让 PcmSpool.complete；具体实现须验证最后字节、状态落盘和取消的竞态。完成查询可以重试读取，但绝不能借此重新发起 TTS。

服务器“完整接收” ≠ 手机“完整播放”。CallService 仍以 AudioTrack 实际开始及完整播放回调决定提交本轮关系/记忆效果；不由服务器替手机宣布已听见。挂断、返回、手动打断和音频焦点丢失仍取消原播放会话，同时通知服务端停止上游读取。取消是停止后续工作，不保证外部服务已免计费。

HTTP成功头已发出后，上游若报错不能在 PCM 后追加 JSON，也不能正常结束并伪装完整成功；通过终止流与请求状态体现失败。开始传音频前的认证/配置/额度/上游错误返回受控错误码，不回显提供商原始正文。

## 手机具体增量范围

- FishClient：保留现有台词清理、音色/模型校验与直连实现；新增可替换传输边界和云端实现，不直接重写整个类或另造播放器。
- VoicePlayer：Session 改持有传输接口，沿用网络/音频执行器、PcmSpool、AudioTrack、焦点、暂停、取消和缓存；云端完成校验接在现有接收完成边界。
- VoiceCache：目前 key 与 API key 摘要相关。云端模式改用不含密钥的服务配置标识及音色/模型/格式修订作命名空间，避免设备令牌轮换导致所有音频重新计费合成；保留旧文件、已保存语音和直连缓存读取能力，不批量删迁移。
- CallService：仅调整 TTS 配置准入与传输选择；云端模式不再检查手机 Fish 密钥，但原聊天模型、ASR、待回复文字限制和 CallLaunch/CallEpoch/turnId 保护照常。
- WebActivity 与 settings：通过原生桥接配置与检查云端 TTS，设备令牌不暴露给 WebView；不改变聊天主页面结构。
- ConversationEngine、日程、关系、记忆、ASR、CallTurnEnd 和现有完整播放提交规则不在本次迁移中重写。

## 必须覆盖的测试

1. 未认证/已撤销设备、错误音色/模型/参数、超长文本或字典、并发/额度不足均在付费请求前拒绝。
2. 假上游正常流、首音慢、分块切分在奇数字节、空响应、截断、超限、错误内容类型、401/402/429、超时和中途错误。
3. 手机断线、挂断、立即再次播放、迟到回调、上游结束与取消同时发生、完成状态查询暂时失败、进程重启及请求ID重放。
4. 不完整音频不缓存、不当作完整播放；服务端传输完成不会提前提交关系/记忆效果。稳定缓存命中不发新TTS；切换模式与令牌轮换不误用另一配置音频。
5. 模拟上游分别测试直连与显式代理，验证凭据不外泄、禁止重定向与任意目标转发。
6. 新云端 schema 与运维旧备份兼容、升级失败保留、恢复后的请求未知状态与重复计费防护。
7. 真实 Android 麦克风/音频焦点/锁屏/耳机/Vivo后台与真实 Fish 的质量、延迟、费用独立报告；离线和假服务通过不替代真机或真实服务。

## 发布与回退

采用独立云端开发分支与可校验版本包；升级前备份，保留旧程序/配置/脚本。手机使用原签名并保留旧APK；版本号以编码时最新主工程为准，不预占或回退当前其他开发版本。每次 Android 发版同步应用内更新公告、功能说明、验证范围和交接。

首期不部署本地大模型/本地 Fish Speech，不迁移 ASR、聊天模型或完整角色云端执行权，不加入第二套账号系统和管理网站。两核2GB先承载低并发 API 中转，实际音频出口带宽、代理可达性、流控内存与延迟要测量后再扩展。

官方依据：[Fish TTS v1](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech)、[HTTPX 异步流](https://www.python-httpx.org/async/)、[HTTPX 代理](https://www.python-httpx.org/advanced/proxies/)。本计划只查文档和当前源码，未安装出口组件、修改服务器、上传密钥或发起真实合成。
