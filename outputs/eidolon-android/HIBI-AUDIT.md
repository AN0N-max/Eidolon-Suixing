## 1.2 本地后台适配

每日主动计划、WorkManager网络任务、持久聊天未读及入口红点已补入，详见DEVELOPMENT-1.2.md与RELEASE-1.2.md。此调度是APK本地实现，不照搬Hibi服务器常驻任务；多角色共同行程、早间专属事件搭话、表情包和实时通话仍未完成。

## 本轮实现细节

- `tools/hibi-hearts-manifest.json` 固定 28 个源文件的 Git blob SHA；`tools/import-hearts.py` 离线验证缓存原文后构建 `assets/hearts.json`，并保留 `assets/hibi-hearts-source/*.toml` 原注释。文件缺失、被改动、角色不匹配或未成年含恋爱配置时拒绝导入。
- `HeartsData` 处理纯档案校验、五档表现和判断参考；`Hearts` 在 Android 上共用缓存及开关。Jev/百炼仅扩充原 affinity 问题的 instructions，不改其他问题及概率格式；兼容接口在原好感判断请求加入相同参考。原有 Progression 是唯一计分路径。
- 生成时根据本轮预测关系阶段选择表现，但副作用仍需在回复正式投放时提交；废弃回答不会因为 Hearts 再计分。未知角色继续使用原通用规则。
- 开关位于“设置 → 聊天与关系 → 记忆与关系设置 → 角色专属关系”，默认开启；关闭好感评估时不注入关系阶段表现。查看原始关系档案入口位于角色关系面板。

## 0.9.21 洗澡行程实现与检查边界

- 按固定提交 `schedules.py` 的 `draw_bath` 规则本地生成：睡前 60–120 分钟开始，按 5 分钟步进；28 份关系档案中的角色默认泡澡，Luca 与 Mikoto 为淋浴。泡澡时长 30–50 分钟，淋浴 15–25 分钟。随机结果随每日行程一并存储；同一天重建/读取不会重新抽取，也没有新增模型请求。
- 角色时区用于跨午夜的洗澡开始、结束时间计算。开启作息时显示当前“正在洗澡”状态，并暂停主动搭话。用户在预计洗澡时段发消息且开启延迟回复时，原回复延迟的随机等待与洗澡结束时间取较晚者；回复上下文提示可说刚洗完，不要求描述沐浴过程或身体。若延迟回复关闭则维持现有即时投放设置。
- 既有已保存日程保持原样，不回填洗澡安排；新生成成功的日程添加 `bath` 子对象，普通加密备份沿用 `schedules` 字段即可。没有改动 SQLite 版本。
- 离线检查覆盖角色泡澡/淋浴时长范围、睡前时间范围、正在洗澡状态、跨午夜时区日期、延迟回复等候时间以及现有行程备份验证。未在真机上确认状态轮询或系统后台实际投放。

## 0.9.19 来信实现与检查边界

- 新表 `letter_plans` 只供原生计划/写作/投放与加密备份读取，不向 WebView 导出暂存正文。投放后进入既有 `writings`，原筛选、阅读和聊天回忆才可取得正文。
- 单次生成任务需要联网，投放任务不要求网络；开机/升级/时间变更恢复，应用快照另做离线到期消费。关系冷却、结束会话、等待回复不发起新来信生成。关闭自动来信暂停但不清空暂存。没有新增信件系统通知或悬浮窗。
- 新增 38 项纯 Java 来信计划检查；SQLite 模型验证升级保留、唯一计划、到期消费、失败回滚、版本隔离和恢复不重复；模拟桥接检查设置规则、保存以及原信箱筛选/阅读。均未调用真实 API，未在 Android 真机验收。

## 0.9.20 日记实现与检查边界

- 隐藏页列始终从 WebView 快照剥离；原生 `diarySecret` 在事务内检查最新关系/冷却及好感开关。已打开阅读页随静默刷新/正式回复更新可见范围。旧日记没有隐藏页时不重新生成。
- 前台与后台恢复只在已有记忆分析请求加入可选素材字段，要求最新用户原话；取消/新批次/记忆 epoch 改变时不留下素材。记录和投放不额外计分。
- SQLite 与备份升至 v10，保存独立隐藏页已读与自动日记尝试；保持 v1–v9 导入。
- 新增 46 项 Java 检查、SQLite 升级/阅读标记/次数限制/回复与事件原子提交模型、私密页 UI 模拟授权/撤回/搜索隔离检查；没有真实 API 或 Android 真机验证。

## 0.9.22 重要的一幕

直接读取固定提交 affinity.py 的 SCENE_TIERS、SCENE_TURNS、SCENE_SLACK、DOOR_GAP、SCENE_LIFT、scene_prompt 与门槛逻辑，并使用现有 hearts scenes 档案。Java 改写位于 HeartScenes；聊天、送礼与约定共用门槛；前后台生成共用提示与投放凭据。默认关闭，开启时保留已有高关系；功能暂停期间普通分数仍可变化，重开保留已达到的阶段。版本凭据在正式回复事务中消费，新触发不消费首轮，废弃/取消/旧凭据不推进，已结束会话也不推进。

本地适配：第六轮如本轮分数已跌离门槛五点或冷却则暂停；没有照搬服务端邀请主动搭话；角色关键剧情是否自然由用户实际模型验收。纯Java检查覆盖两道门槛、六次正式消费、旧凭据/开关版本、触发与投放分离、旧关系保留、加密备份、未成年信赖及并发送礼；模拟设置UI覆盖开关显示、进度及设置返回滚动。没有Android真机或真实模型验收。

## 0.9.23 误判申诉

直接读取固定提交 appeals.py 与 affinity.py 的 give_back/EXPLAINED。新增 AppealData/AppealStore，本地原生验证角色最新回复、逐条扣分凭据、当前会话及冷却状态；同一事务返分、清对应hurt/out计数、记录每日额度与已申诉标记。后台恢复和前台生成均暂存纯聊天判断，正式投放才生成可申诉凭据。旧消息无凭据，不推测扣分。全角色每日三次，制作人时区且时钟回退不重置；不新增模型调用。

本地差异：有待回复消息时先处理；角色已有新用户消息也不能申诉旧回答；只在下一次用户聊天回复注入解释，提示在正式投放时消费；SQLite和加密备份v11包含凭据及额度。恢复备份会恢复当时的状态。21项Java检查、SQLite升级/回滚/一次性CAS模型、界面模拟确认/取消/单次标记通过。没有真实API、Android设备或端到端恢复验收。
