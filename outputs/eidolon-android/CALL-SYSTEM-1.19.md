本地审查：FishClient仅有Fish合成接口（https://api.fish.audio/v1/tts），没有STT。VoicePlayer已经具备PCM流读取、AudioTrack播放、缓存、焦点、暂停和取消；原先绑定Activity生命周期。ConversationEngine负责普通/恢复聊天的提示词、人设、关系、检索、记忆与生活快照。ModelClient、TemporalRuntime、RecentTimeFacts已保留角色时区和历史日期依据。ChatStore通过pending_replies暂存生成结果，deliverPending事务提交消息及效果。WebActivity原生桥接，assets/ui/app.js负责界面。原Manifest只有网络、通知、后台写作/回复等权限，没有麦克风前台服务。

## 模块与流程

新增CallService：原生前台服务拥有callId、turnId、麦克风、识别、音频路由、焦点、挂断与30分钟/60轮上限。CallEpoch隔离旧轮次/旧通话回调，并要求实际开始播放后才能取得一次性提交资格。CallStore存本机通话元数据与暂存轮次的绑定；数据库和备份升级v16，恢复时只恢复记录，不恢复麦克风或付费请求。

识别提供两种路径：Android SpeechRecognizer（系统选择的识别服务，可能联网），或独立CallHttpAsr。后者直接请求用户配置的完整HTTPS multipart音频转录地址，使用独立加密密钥，16kHz单声道PCM在内存转成WAV，不写原始录音文件。最多采集30秒；基于音量阈值和静音结束一轮，噪声可能影响分段，不是流式ASR。空闲超时不继续静默采音。

识别文本 → 同一角色/同一文字会话的beginPendingUser → 原ConversationEngine → 暂存回答及效果 → 原VoicePlayer/Fish合成并流式播放 → AudioTrack播放头确认开始且完整播放完成 → 条件投放和效果事务提交。失败、打断或挂断会取消识别、HTTP、模型、合成、音频排队及播放，未完整播放的回答不作为已听见交流。识别文字留在本机聊天，但通话不自动提取长期用户事实、时间记忆、日记摘要或约定，避免识别错误直接成为稳定事实。

角色仍复用人设、关系、近期文字和通话上下文、记忆检索、生活/情绪/行为规划、角色时区、近期话题日期。通话记录提供真实接通/结束时间与已完整播放轮数。HTTP识别按VAD首次声音的单调时刻回推消息创建时间，末次声音用于停讲延迟测量，避免识别响应跨午夜改变原话的日期锚点。系统识别使用系统给出的开始讲话回调时刻，缺失时回退到停讲回调，极近午夜边界受系统回调延迟影响。

VoicePlayer新增结构化实际播放/完成/失败回调，旧文字语音逻辑继续使用原状态回调。电话持有独立焦点，通话播放器不重复申请焦点。双语时播放日文、显示对应字幕；仅中文模式播放中文。模型完成后才将完整语义台词交给TTS，不把未闭合标签或半句话当成音频分段，因此第一版不是自然全双工，也没有LLM首段直接串接TTS。

## 分阶段结果

1. 主动拨打：聊天页电话入口、显式数据说明、权限申请、实际连接/聆听/识别/思考/播放状态、多轮、字幕、静音、扬声器、打断/重新聆听及通知挂断。模拟原生桥接和取消/编码规则验证通过；真机和真实服务未验收。
2. 生命周期：应用Context服务、mic/mediaPlayback前台服务、可操作通知、有限唤醒锁、音频焦点丢失结束通话、设备断开停止当前轮并提示重新聆听。Activity重建查询服务，不重新生成回答；进程重启结束旧通话，不自动重试未知付费结果。原生音频、锁屏和蓝牙仍待真机验证，不能以源码/假接口检查代替。
3. 角色与并发：同角色有待回复文字时拒绝拨打，提示先处理；通话时该角色不发送新文字、普通等待卡隐藏，暂存结果由电话管理。其他角色文字/通知正常，非电话语音播放不能抢占音频。主动搭话暂时延后，原有效期仍适用。采用callId/轮次标识、持久revision和原投放事务，防止重复计分/写记忆。
4. 主动来电：独立开关默认关闭，依赖原主动搭话设置、允许角色、关系、联系间隔、作息、免打扰及总额度。最多每日一次且至少间隔24小时；允许将一个已到期但尚未执行的联系机会替换为来电邀请，避免同时发消息和来电。系统实际接受通知后才保存邀请记录；接听/拒接/未接由本机状态记录，不影响关系。接听前无采音、模型或TTS。使用普通/CallStyle通知，不申请全屏或悬浮窗权限。系统未执行后台任务时不伪造来电；超时状态会在下次检查补算。

## 数据、资源与费用

音频→系统所选识别提供商或电话设置里的HTTPS识别服务；识别文本/必要角色上下文→已有聊天/判断模型配置；角色台词→Fish Audio。识别服务密钥通过Vault单独保存，公开日志和仓库不包含密钥、录音或真实通话文本。原始用户录音不保存；合成语音仍使用已有本机缓存与删除机制。通话记录及文字随v16加密备份导出，接口密钥与设备权限不在备份中。

真实延迟及金额：未测，未调用付费服务。界面在实际使用时测量停讲→识别完成、识别完成→最终聊天模型首个content片段（可能含JSON外壳，不等同可播放的语义段）、模型首个content片段→实际首音、停讲→首音，上一轮数据保留可查看。HTTP识别每个有效轮次最多一次；聊天沿用原设置，通常最终生成一次，启用关系/剧情判断时可能再有一次判断；TTS缓存未命中才请求。没有失败自动重试，不提供未经计费依据验证的费用估算。

## 验证矩阵及限制

| 场景 | 当前验证层级 |
| --- | --- |
| 拨打、多轮状态、字幕、静音、打断、挂断 | 实际WebView页面JS配假原生桥接；无真实录音/服务 |
| 拒绝麦克风 | 假原生错误反馈；系统权限对话框待真机 |
| 讲话/模型/播放阶段挂断、旧结果迟到 | 生产CallEpoch取消/播放提交令牌测试；Service回调入口检查 |
| 网络失败恢复 | 无自动重试、旧revision拦截规则与界面重试；真实断网待真机 |
| 耳机/蓝牙/焦点 | 原生回调已接入；硬件路由待真机，Android26–30蓝牙可靠性未验收 |
| 锁屏、后台、重建、进程恢复 | 持久元数据及恢复入口检查；系统执行行为待真机 |
| 识别错误、未播放不提交、重复效果 | 关闭通话自动事实提取、一次性听见令牌及SQLite事务回滚检查 |
| 电话/延迟文字/主动消息并发 | 持久绑定、同角色限制、共享额度和普通等待入口检查；并发SQLite规则测试 |
| 午夜/时区 | 既有时间回归，加语音时间回推测试 |
| 长通话资源及费用 | 有界PCM/WAV、超时、取消、30分钟/60轮上限；真实长通话资源与金额未测 |
| 主动来电接听/拒接 | 假桥接验证接听前不采音，通知/冷却/额度源码检查；系统通知实机未验收 |

不可据此宣称真机或真实语音服务已通过。Vivo/iQOO后台限制、系统识别服务可用性和接口兼容性仍需实际设备验证。没有自然语音打断：角色讲话时识别停止，使用明确“打断/重新聆听”按钮。不能保证强行关闭应用后精准来电。

备份v16允许因打断、挂断形成的连续用户消息或尚无回答的话轮，不伪造角色回复补齐；仍拒绝没有用户来源的普通角色回答。恢复备份前结束活动通话，旧请求不会回写到恢复后的会话。
