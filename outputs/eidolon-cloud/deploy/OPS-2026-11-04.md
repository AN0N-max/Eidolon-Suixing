# 运维脚本 2026.11.04.1：步骤、调控与验收

本轮仅扩展部署工具，服务包仍为 0.1.0.dev1，不修改业务框架源码或数据库 schema。手机真实主工程现为 1.28/code84、SQLite/加密备份 v18；旧云端交接记录中的 1.22/v17 已过时，不能覆盖当前工程。

## 操作顺序

以 Ubuntu 普通登录用户执行，不要给整个脚本加 sudo。下载后使用带版本的文件名 `eidolon-cloud-setup-20261104.py`，保留原来的 `eidolon-cloud-setup.py`。两者均指向原有安装与数据目录；新版内部使用相同 setup.lock 防止并发操作。

```bash
python3 ~/eidolon-cloud-setup-20261104.py check
python3 ~/eidolon-cloud-setup-20261104.py service-install
python3 ~/eidolon-cloud-setup-20261104.py status
python3 ~/eidolon-cloud-setup-20261104.py backup
```

`service-install` 的顺序为：校验服务名/配置/依赖与 sudo 可用性 → 生成并验证 service 候选 → 校验并备份已有云端数据库 → 独占创建 service 文件 → 优雅停止已核验的旧进程 → 归档旧 PID 记录 → 启动并验证健康与认证 → 启用开机启动 → 输出回执。未知或修改过的 service、drop-in、待重载的 unit 均会拒绝接管，不覆盖。

依赖不完整时会停止，保留现有环境；不要在服务运行时重装虚拟环境。首次尚未装好框架可先用新版 `install`，已完成本次截图所示部署的服务器通常无需重复安装。

接管后统一使用新版脚本。原脚本仅作留存，不再用于启停。新版识别 systemd 管理状态，`start/stop/restart/status/logs/install` 不再另起 nohup 进程；后端自身的 runtime.lock 继续保留。

## 调控命令

```bash
python3 ~/eidolon-cloud-setup-20261104.py start
python3 ~/eidolon-cloud-setup-20261104.py stop
python3 ~/eidolon-cloud-setup-20261104.py restart
python3 ~/eidolon-cloud-setup-20261104.py status
python3 ~/eidolon-cloud-setup-20261104.py logs
python3 ~/eidolon-cloud-setup-20261104.py service-disable
```

`service-disable` 停止服务并取消开机启动，保留 service、源码、数据和备份；重新执行 `service-install` 可在验证后再次启用。健康检查不等于完整业务接入，仍应看到 `domainConnected:false`。重启服务不代表重启服务器，脚本不执行 reboot。

运行仍限回环地址 127.0.0.1:8787，诊断任务默认关闭。没有新增公网入口、手机 VPN、模型配置或用户账号。服务以原登录用户运行；限制写入路径、使用非 root 进程、SIGTERM 优雅停止，不使用强制 SIGKILL。运行输出交给 journald 轮转并设置单服务日志限速，不修改整机 journald 的保留策略；实际磁盘限额需结合服务器现有配置验收。

## 备份与恢复

备份默认为 `~/eidolon-cloud-backups/` 下的新目录，包含 `database.sqlite3` 与 `manifest.json`。使用 SQLite Online Backup，包含已提交 WAL 数据；验证 schema、数据库完整性、外键和 SHA256。不输出令牌明文，不自动删除旧备份。manifest 是本机一致性校验，不是防恶意篡改的数字签名。

```bash
python3 ~/eidolon-cloud-setup-20261104.py backup
python3 ~/eidolon-cloud-setup-20261104.py backup-check --backup ~/eidolon-cloud-backups/实际备份目录
```

只有明确需要回退数据时才恢复。以下路径和摘要必须取自所选备份，不能直接复制占位文字：

```bash
python3 ~/eidolon-cloud-setup-20261104.py stop
python3 ~/eidolon-cloud-setup-20261104.py restore --backup ~/eidolon-cloud-backups/实际备份目录 --confirm-sha256 实际64位摘要
python3 ~/eidolon-cloud-setup-20261104.py start
```

恢复要求服务和旧进程均已停止，并持有原运行锁；再次验证备份后冻结输入、生成恢复前快照，再使用 SQLite 备份事务恢复现有数据库。选错摘要、未知 schema、无关数据库或留存失败会拒绝写入。恢复失败保留输入和快照，不自动启动服务；成功也不自动启动，便于先检查回执。复制中断的回滚行为已有真实 SQLite 测试，实际服务器仍需另行验收。

恢复会回退消息、游标和设备认证状态，包括重新出现备份时尚未撤销的设备令牌摘要。恢复后应检查并重新撤销不再使用的设备。当前仅支持基础框架 schema 1，不可拿它恢复 Android 的 eidolon.db、手机备份或未来未经审查的业务 schema。

当前恢复命令要求现有云端数据库存在且有效，以支持有留存的数据回退；整机丢失后的空目录灾难恢复尚未实现。备份只覆盖云端 SQLite，不包含系统配置、模型密钥或虚拟环境；源码包、脚本与服务器配置须另行保留。同机备份不是异机容灾，也尚未安排每日自动备份。

## 本轮验证及限制

- 新增 18 项运维测试，包含实际框架数据库/设备认证/诊断收件箱的快照恢复、真实 WAL 备份、摘要/路径/schema 错误拒绝、恢复前留存、复制中断回滚、服务预检失败、激活失败、重复接管及已有 service/drop-in 保护。
- 连同旧部署测试与原有框架/真实 Java 日切桥接，当前全部测试共 48 项。systemd 控制使用模拟器测试，不能写成实际 Ubuntu 服务已安装。实际 Linux service 文件会在执行时调用 systemd-analyze verify。
- 原 Android 1.22 摘要检查发现 12 项已有后续变化；这些文件与当前发布暂存内容一致（忽略换行），原摘要文件保持不变。已核对实际主源码和最新 1.28 交接，不将旧基线重置为当前通过，也不迁移/修改这些业务文件。
- 浏览器创建服务器入口后可看到该 URL 的新标签，但读取页面连续超时并重置，未进入可确认的 Shell。SSH 严格检查也因缺少已验证 ED25519 主机指纹而拒绝；没有绕过检查。因此本轮未在 Ubuntu 执行新版脚本，未验收开机恢复、真实进程故障恢复或生产数据恢复。
- 未修改手机应用、生成新 APK、改变速云代理、开放端口或调用付费 API。
