# 闪耀色彩中文剧情：来源与导入验证

结论：SCTranslationData 的剧情 CSV 与当前 0.5 APK 导入器直接兼容，无需转成另一种表格结构。整个仓库 ZIP 不能直接一次导入；应仅选择 data/story 中的剧情并拆成多个 ZIP。此结论来自真实样本，不是完整库或手机端验收。

## 来源

- 主数据仓库：[ShinyGroup/SCTranslationData](https://github.com/ShinyGroup/SCTranslationData)
- 剧情目录：[data/story](https://github.com/ShinyGroup/SCTranslationData/tree/master/data/story)
- 在线翻译/剧情浏览工具：[sc-viewer 说明](https://docs.sc-viewer.top/)，支持磁盘 CSV 和 GitHub 现有翻译。
- 汉化插件：[biuuu/ShinyColors](https://github.com/biuuu/ShinyColors)，不是应当导入的剧情目录。
- 棱镜之歌 SCSP 是另一游戏的数据格式，不能直接按本次页游剧情解析器混入。

固定样本版本：`60d451090aea86631815a0522238eb5f3d196e1b`，仓库返回的提交时间 `2026-06-16T04:18:42Z`。GitHub 文件树未截断；当前 data/story 目录含 5,623 个 CSV，总计 31,857,774 字节（约 30.38 MiB）。文件数不是去重后的剧情数，也不能据此认定全部原作剧情都已翻译。

## 实测

- 从 36 个目录各取代表样本，并加入最大的 8 个文件，共 44 个 CSV。
- 全部表头为 id,name,text,trans，全部含 info 来源行。
- 使用 APK 同一份已编译的 StoryFiles.parse：44 个解析成功，44 个来源编号，0 个异常。
- 使用 APK 同一份 StoryFiles.load：44 个样本构成的 ZIP 全部读取成功。
- 42 个样本识别到至少一位应用现有角色；2 个联动样本（露比、有马加奈）没有现有角色的出场名，因此不会进入现有角色专属检索。
- 样本共有 3660 条正文行，其中 3559 条译文非空；有空译文的行会保留日文，不能宣称样本每行都已汉化。
- 使用真实样本生成的词索引，在 SQLite FTS4 中验证关键词匹配和出场角色过滤。命中统计：{"制作": 34, "练习": 7, "约定": 1, "偶像": 14}。此为测试样本命中数，不是全库数量。

## 当前可用导入方式

1. 从主仓库下载原始资料，选择 data/story 下需要的角色或活动目录，保留 CSV 文件及目录名称。
2. 每批建议 1000–1500 个 CSV；每个 ZIP 解压读取量不得超过 32 MiB，单文件不得超过 4 MiB，一次不能超过 2000 段。可按角色/活动拆包。不要把 data/etc、公共 UI 表、插件代码等一起作为剧情导入。
3. 手机打开「设置 → 剧情库 → 导入 CSV / JSON / ZIP」，依次选包。
4. 导入器以 info 行中的剧本编号识别内容；同编号保留已有 CSV 译文优先级。原失败结局规则会过滤对应脚本。
5. 先按角色和关键词查找，再打开「查看原文与来源」确认。

本次仅下载了验证用样本，没有把整个库导入手机，也没有改动 APK 或把剧情打进 APK/源码包。若要整库使用，还应对全部文件做解析、去重、空译文和角色覆盖检查，并按上述限制拆包。整体剧情库通常超过当前加密备份的剧情容量上限，需保留原始导入文件。
