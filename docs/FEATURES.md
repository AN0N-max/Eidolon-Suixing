# 1.28.5 功能说明：交流之后留下后续

## 持续的小目标

继续使用character_life里的goals/events及既有阶段规则。保持少量目标：一个进行中或暂时搁置的目标，最多四个近期目标、十二个历史归档；每个2–5个阶段。记录形成时间/来源、当前阶段、最近进展、困难、方法、下一步、暂停和取消原因及有界经过。阶段完成仍由实际观察到的虚拟活动或原有明确结果确认驱动。错过计划、仅过夜、用户一句建议都不会自动完成阶段；考试比赛结果仍等待确认。

模型可以在正式回答中自然选择继续、调整方法、搁置、恢复或取消，候选必须引用本次实际说出的台词和已选目标版本。它不能凭一句新台词直接增加进度；只有实际投放才保存这些候选。生活状态页增加搁置/继续和经过查看，继续使用lifeEdit的revision保护。目标关闭后不当成当前待办，历史归档保留简短来源与经过。

## 用户建议如何影响后来

共同经历使用现有事件ID和目标阶段，记录原来的困难/对应助手消息、用户建议原话及来源、角色是否只是考虑/打算尝试、后来哪一次虚拟活动绑定了方法、结果和下一步。每个角色最多保留十二条此类关联（含明确形成的称呼/分享习惯）；可以在生活状态页查看和撤回，撤回后后续提交可清理并释放空间。

“你建议了”不等于“她做过了”。只有角色已明确表示打算尝试、之后的对应阶段活动在意向送达后才开始并完成，才记录为真正的虚拟尝试。阶段已过却无执行证据会解释为未记录尝试，不长期装成待办。虚拟尝试完成后，正式回答可一次性补充本次练习的具体感受和下一步，保存为虚拟反思；同一尝试不会因后来一句夸奖反复改写结果，也不会冒充考试获胜等外部结果。

聊天、主动搭话、来信、日记和摘要读取同一份连续性投影。新进展才优先成为主动话题；投放成功后已选过的同版本话题不反复主动提供。没有结构标注的旧服务只记录该话题已被使用，不假称它确实分享了结果。用户主动追问仍可读取已分享的内容。日期从建议/尝试原时刻和原时区计算，三天前不会一直叫昨天。来源限定当前角色，不把其他角色的私人相处当亲历，也不根据高好感批量生成专属回忆。

## 会修正的用户理解

复用personal.memories，不另建画像库。自动理解使用已有后台记忆请求的可选结构；事实主体来自可核对的用户原话，模型提供的心理分析不作为正文保存。区分明确陈述、长期偏好、暂时状态与不采纳的模型推断。条件补充保留前面的兼容内容，例如“喜欢独处；补充条件：不是讨厌相处，只是人多容易累”；明确否定则替代旧版本，保留来源、时间、版本和替代链。

本轮新理解先形成内存预览，实际最终回答请求已经读取它；没有提前写数据库。随正式回答投放后才通过原personal三方合并提交。memoryEpoch隔离迟到的旧请求；旧总结在理解版本改变后不再作为当前画像使用，过期总结预览也不能覆盖新修正。暂时状态到期后不当成长久人格。自动事实仅供实际告知的角色使用；手动保存仍可以作为各角色共享参考，明确允许共享的信息也继续注明听说来源。

现有长期记忆页可查看原话、条件和修订，编辑、撤回或清空。撤回新纠正不会自动复活被否定的旧结论。来源在导入后缺失时保守不参与自动理解，可由用户核对和编辑，不伪造来源。

## 既有状态影响表达

现有人设、缓慢兴趣变化、情绪及具体困难、关系边界和本轮意图一起进入表达依据。解释时先答具体问题，低精力影响节奏，未解决困难不会因一次称赞被删除；偏好仍沿既有跨日经历规则缓慢变化。称呼或分享习惯需要真实用户要求和角色实际回应来源。可以温和分歧，不强制同口吻、不固定问句结尾。没有新增离线扣分、催回复、假在线/已读/正在输入、无限补发或恋人承诺系统。

“记忆与关系设置”增加连续性开关；生活模拟仍受生活状态开关控制，自动理解写入仍受自动记忆控制，关闭关系评价时不会在新投影中偷用旧亲密档位。新功能追加独立模型请求预算为0，复用既有后台分析和正式回答；既有日程已知截断重试等独立预算未扩大。输入token会增加，模型自然度不能由离线假服务证明。

每次最多选2个相关目标、2条共同经历、1条有来源的相处习惯、3条当前用户理解、6条短来源。分析候选只带有界事实字段，不复制完整来源历史；最终记忆来源只投影初始/最新两个摘要引用，原始详细依据仍在本机记录。旧服务不返结构时，继续聊天且不冒进提交无法核对的候选。

## 隐藏日文仍保留中文分段

# Eidolon 随行：手机上的日常聊天

Eidolon 随行是一款独立Android手机APP。聊天记录、记忆、每日行程、计划与待投放回复在手机本地保存和管理，不用部署服务器，也不用让电脑一直开着。AI回复使用自行配置的外部API；联网生成时，相应消息上下文会发送给服务商，因此“本地应用”不等于“离线大模型”。

## 延迟回复：发出消息后，等她有空再回

**入口：设置 → 提醒与后台 → 根据行程延迟回复。**

你可以发一句话，然后切去做别的事；回复准备好后会暂存在手机里，等到本地安排的时间再进入聊天。回来时继续之前的话题，不需要守着生成页面。开启延迟回复时，可以从A的会话切到B，A的回复不会抢走B的页面。

用户消息先保存，约4秒合并连续输入。等待时间按发送时的角色行程分类，从你设置的范围中抽取，不为“要等多久”额外请求判断模型。实际投放还受模型完成时间和手机后台调度影响。

| 情况 | 默认等待范围 | 可以怎样调整 |
| --- | --- | --- |
| 空闲或休息 | 5～25秒 | 设置最短、最长时间 |
| 吃饭 | 30～120秒 | 按自己的聊天节奏调整 |
| 排练或工作 | 120～480秒 | 工作时可以等久一点 |
| 没有明确行程 | 5～25秒 | 使用默认范围，不猜测活动 |
| 正在睡觉 | 默认等到预计醒来时间 | 也可允许困倦回复 |
| 正在洗澡 | 至少等到预计结束 | 在原延迟基础上延后 |

待回复状态提供立即接收、取消和失败重试等操作。已经生成的回答不因本地延后再次生成；失败重试是否需要重新请求，取决于任务停在哪一步。关闭额外延迟不等于取消模型生成时间与约4秒输入合并。

## 主动搭话：她也可以先来找你

**入口：设置 → 提醒与后台 → 主动搭话。**

开启后，应用会根据最近交流、关系、联系间隔、角色范围与每日额度，给合适的角色安排主动消息。可以查看今天的计划、完成情况和未安排的原因。

它不会为了填满次数重复找同一个人。当前版本允许上一条主动消息还没得到回复时继续获得机会，也允许普通聊天等待期间安排；免打扰、作息和预算仍然生效。筛选与排程在本地进行，到期生成消息才使用模型。

## 消息弹窗：使用手机自带的通知横幅

**入口：设置 → 提醒与后台 → 主动搭话 → 系统通知与提示；系统通知设置中管理悬浮通知。**

1.12只使用Android系统消息通知：在其他页面或应用外收到合适的提醒时，由系统决定是否显示顶部横幅、通知中心记录、声音和振动。点击对应消息通知进入相应角色与会话。

**应用内及跨应用自绘消息卡已经取消**，无需申请“显示在其他应用上层”权限。正在阅读对应会话时，消息直接更新，不额外弹一张卡。横幅的形状、停留时间、位置、锁屏展示与勿扰行为由手机系统决定，应用中的通知开关不等于系统已经允许悬浮通知。

## 未读与桌面角标：看见消息后再算已读

角色头像和底部“对话”显示未读数，超过99显示99+；只打开APP或对话列表不会把所有消息清空为已读。实际看到的消息才被确认，全部读完后再同步清除角标。

Vivo／iQOO提供额外兼容更新；数字、圆点、位置是否展示由系统桌面决定。桌面角标总开关没有可靠统一查询接口，APP不把通知类别的返回值误报成总开关已关闭。未读为0时，没有角标属于正常情况。

## 行程、信件和日记：让对话有一些后续

**入口：设置 → 生活日常。**

角色可以有大致的每日安排和各自的作息；这些安排会影响回复语气、延迟和主动搭话。行程页按档案时区在03:00前保留上一日安排，03:00起切换当天；旧记录仍然保留，新的生成可能稍后完成。

可以按需开启信件、事件日记、约定与纪念日，查看写作计划和已经保存的内容。日记依据已有互动整理，不把应用生成的安排当作已经发生的经历。部分内容有关系阶段与事件条件，不保证每天都有。

## 记忆、设定与外观

**入口：设置 → 聊天与关系 / 档案与外观。**

可以查看和调整记忆、时间线与聊天总结，逐角色编辑提示词，设置称呼、时区、个人头像、字号和深浅主题。总结支持先预览再保存，不把未知日期擅自补成今天。记忆是对历史的整理与检索，不代表每次请求都包含全部聊天原文。

## 剧情索引：自行找资料，再导入

**入口：设置 → 聊天与关系 → 剧情库。**

APP和公开仓库不包含完整原作剧情库。需要用户自行寻找、整理相关剧情文本，按导入页支持的格式导入，再在本机建立可检索的索引。这里导入的是兼容的剧情资料，不是直接把视频剧集放进应用。

内置的基础角色人设、资料与用户自行导入的剧情内容是不同的来源。没有导入完整资料时，不应将角色回答视为已经检索过全部原作；新增剧情也需要补充导入。导入格式与ZIP打包范围按界面说明操作，早期格式验证见[剧情导入报告](history/STORY-IMPORT-AUDIT.md)，该报告不附带原始剧情文本。

## 后台运行与费用

模型生成、自动信件和日记等可能使用API额度；本地排程、查看计划、同步角标和更改等待时长不因操作本身调用模型。具体调用取决于开启的功能及配置。

回复后台保护可在生成和短等待期间显示临时运行通知；较长等待交给系统持久任务。Android省电、冻结、断网、重启或强行停止都可能影响投放，无法承诺秒级准点或永久常驻。

实际设置入口以当前安装的1.15为准。旧截图里的自绘卡片与样式设置属于历史版本；本页后续配图只采用对应功能与版本的截图。

## 1.19 应用内电话（试用）

入口：角色聊天页电话图标。配置原聊天模型与Fish音色/密钥后，允许麦克风和通知。电话设置可以选择Android系统识别，或配置兼容音频转录的完整HTTPS地址、模型和独立密钥。音频发给对应识别服务，文本发给原模型，角色台词发给Fish合成。应用不保存原始输入录音；合成语音沿用原缓存。

自动轮流说话，讲话后识别并生成完整回答，再播放语音；角色讲话时停止识别，使用明确打断按钮。未完整播放的回答不提交角色效果，识别文字不自动提取稳定用户事实。同角色待回复文字需先处理，其他角色仍可聊天和接收通知。

主动来电默认关闭，每日最多一次、至少间隔24小时，共用主动联系的允许角色、关系、作息、免打扰与总额度。接听前不采音或调用模型，拒接不扣关系。系统通知不保证一定弹出，不申请全屏/悬浮窗。

单次最多30分钟或60轮，真实费用按用户接口计费；未知请求结果不自动重试。当前离线/假桥接验证通过，真实手机硬件、后台与接口仍待验收。详情见[电话系统说明](../outputs/eidolon-android/CALL-SYSTEM-1.19.md)。

## 1.20 电话百炼识别

在角色聊天页点击电话 → 识别服务与主动来电设置 → 阿里云百炼（流式识别）。选择密钥所属地域，填写独立识别密钥，开通所填实时识别模型。默认沿用上游qwen-audio-3.1-asr-flash-streaming；普通聊天模型不能直接代替语音识别。旧系统/HTTPS配置继续可用。

声音持续发送到对应地域百炼，不需要电脑后端，不保存原始录音。临时文字显示字幕，服务判定句尾后调用原聊天模型并播放Fish角色语音。识别流式不代表自然全双工，仍有明确的打断按钮。静音超时、断网或挂断会停止本轮，不自动切换地域或重试；听不到有效发言前的采音也可能计费。

离线生产协议与合成音频/假连接测试通过；真实百炼服务、手机音频、实际延迟与费用尚未验收。[配置与验证说明](../outputs/eidolon-android/BAILIAN-CALLS-1.20.md)。

## 1.21 双向表情包与图片

聊天输入栏的“表情”可导入PNG/JPG/WEBP/GIF首帧，分类搜索、收藏、最近使用、编辑语义与角色权限。也可从设置→聊天与关系→表情包资源库进入。角色偏好包括频率、常用情绪、偏好/禁用分类与场景补充；原人设仍决定表达。AI只看到少量本地候选，可不发、只发表情或和文字按序发送，不随机插入。

“图片”使用系统选择器，最多4张，预览后确认，可附文字和点开大图；普通照片不会自动加入表情库。资源在各角色间共享，删除表情目录仍保留历史图片。聊天/翻页/备份保持内容顺序，纯表情不机械朗读资源标签。

设置→模型与接口→图片与视觉识别，默认关闭。明确选择聊天模型支持兼容image_url，或配置独立视觉接口/模型/密钥。音频和电话仍走原服务。图片仅在启用视觉时发往相应服务；已知表情用语义，分析结果按哈希/服务/模型缓存。识别可能出错，不无条件成为长期记忆；图中事件时间不等于上传日期。

独立视觉失败时以未知内容继续交流，原生识图失败可明确跳过识图重试。含附件生成中断不自动重复付费请求。媒体12MB/总加密包32MB为当前备份上限，超限明确失败，不丢图。真实识图质量、原生选择器/编解码和费用未验收。[完整实现与验证说明](../outputs/eidolon-android/MULTIMODAL-1.21.md)。

## 1.22 全屏语音通话

像聊天软件一样，点击聊天页电话图标直接进入全屏拨打。她的头像和模糊背景、实际状态、接通时长、识别文字及双语台词集中展示；静音、手动打断、扬声器、挂断都连接原生服务。当前为静态头像，横竖屏适配。

设置→模型与接口→语音通话设置：选择手机系统识别、百炼流式识别或兼容HTTPS接口，配置地域/模型/密钥、主动来电和自动下一轮，查看通话记录。已有配置不丢失；自动下一轮默认开启，关闭后每轮听完手动开始聆听。仍限制30分钟或60轮，不提供假配置。

采用半双工轮流说话，播放时暂停识别，可手动打断；不是自然全双工。字幕为临时识别和完整生成台词，不逐字对齐声音。拨号和权限等待不计接通时长，合成与播放分开显示。退出/返回取消通话；锁屏/Home由原生前台服务与通知继续管理。

识别音频发往所选服务，文字与上下文发送到原聊天模型，台词发往Fish；各服务可能收费，开发未调用付费API。原始录音不保存，合成缓存沿用原入口。电话与文字共享人设、记忆、关系、日程、情绪及带日期上下文。同角色已有待回复文字需先处理，通话不抢占该回答。真机音频/蓝牙/后台及真实API延迟和费用待验收。[审查与完整文件清单](../outputs/eidolon-android/CALL-UI-1.22.md)。

## 1.23 表情包整包导入

设置→聊天与关系→表情整包导入，也可从表情包资源库进入。选择本地ZIP后，先预览每张静态图片及分类、中文语义、情绪、意图、语气、图片文字和梗意，确认后一次合并进原有资源库。

同图默认跳过，可选择只更新语义而保留原有启用、收藏、权限和统计；包中的角色偏好只补充未设置角色，不覆盖已有设置。不清空聊天，不另建人物系统，表情继续进入原v17备份。输入动图仍按静态首帧处理，没有声音。导入过程本地执行，无付费API请求。

ZIP支持1～400张图片，先校验哈希、路径、大小及角色编号，出错不会报告部分成功。详见[格式与制作](STICKER-PACK-1.23.md)。Android系统文件选择器、实际手机导入/备份往返和模型实际使用质量仍待验收。
