# 1.28.4 功能说明

普通聊天与主动搭话现在使用同一份事件视图和本轮话题依据。提及时间、事件预期窗口、时区、原状态、交谈状态及证据分别保留。日常吃饭、通勤、短途出行窗口过去后，可以按“推定已完成”自然继续话题；推定不等于用户确认，不触发奖励、好感、约定或长期记忆的重复结算。考试比赛只知道时段已过，不代表通过或获胜。“取消／没去／改到明天”在识别到明确同一事件时更新原ID和版本。日期不明或同一事件拿不准时保留未知，不造地点、口味、同行者。

“记忆与关系设置”增加日常事件判断开关。它附加在已有好感/剧情/约定判断中，不新增独立请求；这些判断全部关闭时不会为事件单独调用模型。每轮最多2条候选，Jev/百炼使用原有noul问题，兼容聊天接口使用eventAnswers。候选、原话、时间与主体进入实际请求，程序算日期与窗口。未知/拒绝结果缓存，40项上限并保存淘汰水位；时间窗口推进在本机完成，主动搭话不追加判断请求。输入token会增加；主动搭话输出上限由1200提高至1800，以容纳结构信息，可能增加单次用量。不存在事件补全自动付费重试。

主动搭话先选择一个话题，再生成台词。最终请求包含上一段/当前/下一段安排、距离、计划版本、近期实际投放过的活动自述与用户事件。投放前再次校验当下自述、事件版本和时间窗口；过期回答标为失败并由用户手动重试，不把旧生成状态当现在，也不会自动重新生成。午睡、补觉、夜班、明确临时覆盖、回忆和未来计划继续允许。“晚安”本身没有被禁用。

问台本内容时，优先提供已有资料、用户正文或同一事件的虚拟原创概要；缺正文/概要则准确澄清。新日程的原请求可以附简短虚拟原创topic，保存标题、梗概、人物冲突、进度和感受。聊天中明确要求原创且有关联活动时，可在同一回答准备topic_update，只有投放后才写回同一事件。导入参考、用户材料、虚拟原创分别标来源；本机导入材料不自动等于已核验的原作。

新默认中文/自己的消息16px、日文13px。原生默认、前端回退与CSS统一；已保存的自定义字号继续保留，旧18px设置不会被强制覆盖。中文、可读混写及引用遵循相同字号；收紧段间距和首尾空行，正文仍以安全文本呈现。输入框在外观和状态更新时继续保留草稿、焦点、选区和组合输入。隐藏日文及语音提取沿用既有统一解析。

每轮明确回应、解释、分享、追问或纠错任务，先答问题再表达感受。双语逐段对应，增加可选引用覆盖检查及明确钟表事实冲突检查，不按长度比例判断翻译。兼容旧结构；没有对齐标注时不能凭程序证明语义忠实。不同角色保留口吻，不依据一句话替用户解释人格，也不编造亲历来安慰。

包名和升级签名不变，SQLite仍18；导出备份格式19，旧1–18继续读入，1.28.3不应读入19格式。用户提及事件仅进入现有character_life文档，无第二套数据库。保留旧APK和聊天原文，没有批量改写聊天或复活失败后台任务。

桌面假桥不等于Android真机通过；真实输入法、触摸、音频、后台时序和模型自然度/事实忠实度需另行验证。开发测试没有调用真实模型、ASR、Fish或天气服务。
