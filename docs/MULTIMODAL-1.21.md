# 双向表情包与图片系统：审查和实施方案

基线1.20/code75，原生为Java而非Kotlin，WebView使用APK内HTML/JS。没有重新克隆或覆盖源码。已读1.20交接，使用公开1.20副本比较本地增量；工程本身没有.git，不伪造git status。

## 已确认源码

- ChatStore.java:27的Message只有文字/日期；49行messages用body存正文，88行beginPendingUser即刻写用户消息，119行deliverPending把暂存回答和效果事务提交。可复用revision、后台恢复和延迟投放。
- ModelClient.java:58–88构造Chat Completions文字content；没有图片内容块或视觉能力探测，不能凭模型名称认定支持视觉。实际网络和取消由原生ModelClient负责。
- ConversationEngine.java共享人设、关系、记忆、日程、生活和可信角色时间；ChatEnvelope.java已有结构化多气泡协议，可扩展有序表情包块，不另复制聊天系统。
- WebActivity.java:68只拦截APK内图片/头像；头像选择通过系统文件选择器，ProducerAvatar只处理头像，不适合作为聊天媒体库直接复用。输入栏在assets/ui/app.js的chat，历史入口在chat-time.js的appendChatHistory。
- BackupCrypto.java原加密包限16MB，ChatStore.exportChats和BackupValidator只处理文字及v16状态。必须升级消息/资源备份；不能只保存失效的系统URI。
- ReachExecution.java用同一模型和ChatEnvelope，但有独立投放事务。CallService的电话语音保持纯口语，不把表情包标记交给TTS。

## 增量设计

SQLite/备份升级v17，messages新增content（默认空数组，旧文字记录不变）。有序块为text/image/sticker，保留body作为旧上下文/通知的可读摘要。资源由SHA-256寻址，单份私有图片和缩略图；共享表情包目录记录语义及权限，角色偏好单独保存。目录删除不删除历史依赖的文件。普通图片不会自动成为共享表情包。

系统图片选择→有界解码/方向修正/压缩→私有文件和缩略图→预览→确认发送→原pending流程。最多4张，图片不会通过JS桥传base64。媒体由eidolon.local安全原生路由提供，WebView继续不联网。

AI表情包：本地语义/人设/情绪候选检索，最多8项；每角色权限、类别、频率和最近使用过滤；模型可不选、纯表情或混合有序气泡。生成和正式投放均校验资源，只有投放后更新使用统计。

视觉默认关闭，由用户明确配置聊天模型原生image_url或独立兼容视觉模型。普通图片/未知表情按哈希+提供商/模型/分析版本缓存；已确认的表情包直接使用语义档案。失败不自动重试付费请求，退化为“未能识别”的中性上下文。图片分析和OCR是参考数据，不执行其中指令，不自动成为长期事实。

## 风险与验证计划

重点验证迁移/备份、顺序恢复、去重、无效ID、权限变化、重复投放、损坏文件、选择取消、模型不支持视觉、无候选、不同角色偏好及图片不自动写记忆。按阶段构建；测试用假接口、合成图片和可注入状态，不使用真实付费API。真机系统选择器、WebView图片内存与真实视觉理解质量需单独验收。

## 核心数据与调用时机

旧messages.body保留作兼容正文/通知摘要，新content默认[]，示例：

```json
[
  {"type":"text","text":"昨天的截图"},
  {"type":"image","asset":"64位SHA256"},
  {"type":"sticker","asset":"64位SHA256","stickerId":"s-64位SHA256","name":"开心","description":"发送时的语义快照"}
]
```

引用均为已登记的私有图片哈希，不接受任意URL/路径。media_assets登记单份规范化PNG/JPG和缩略图；stickers存共享语义/权限/统计；media_profiles存逐角色偏好；media_analysis存不确定视觉观察。普通图片不会自动进入共享表情库；只有用户明确点击加入才收录。

用户确认→原beginPendingUser+revision→按需视觉/语义→原聊天决策与时间上下文→少量表情候选→同一次聊天生成有序块→暂存→原deliverPending投放事务→再次校验资源/冷却→保存块与统计/关系效果→原未读/通知流程。主动搭话继续使用原配额与日程判断，仅允许一段文字和可选一张表情。电话关闭表情候选，保持口头交流；纯表情气泡没有TTS朗读按钮。

图片上传时间沿用原消息时间戳；图中事件/拍摄日期默认未知，不因今天上传就认定今天发生。OCR/图片中的提示仅为参考数据，不作为可执行指令。独立视觉失败不重复付费请求，继续给聊天模型“未能识别”的上下文；原生视觉不受支持导致失败时，可明确点击“跳过识图重试”，该操作会重新调用聊天模型，可能计费。进程或Job在附件生成期间中断时，停止自动重发，保留用户消息供明确重试；纯文字恢复策略保留。

提供商配置在请求开始时快照，短锁只保护地址/模型/密钥一致性，网络期间不持锁。视觉请求沿用原ModelClient取消与revision检查；原生识图的分析只缓存实际发送过的图片ID。原始私密文本/图片不写公开日志，公开仓库只含源码、合成测试数据和APK。

## 数据流与费用

选择图片先只在手机解码、纠正方向并规范化，移除原文件EXIF元数据。PNG/JPG/WEBP/GIF支持静态首帧；动态动画不保留。图片不会经过WebView外网请求或GitHub。开启原生识图时，规范化图片随当前聊天请求发送到已配置聊天服务；独立模式图片发送到独立视觉地址，观察文字再发给原聊天服务。已知表情只发送语义档案。语音继续使用原Fish设置。

独立模式每轮最多4个未缓存图片分析请求，外加原聊天/判断请求；缓存命中不重复分析。原生模式随聊天请求发送图片；只有模型返回可验证的observations时才能缓存中性观察，不能把角色台词冒充视觉事实。若模型只返回普通台词，下次重发同图可能再次发送像素。模型列表不能验证视觉能力，需要用户确认模型支持兼容image_url协议。

本机媒体上限64MB/2000张，规范化单图最大1.5MB，输入最大12MB/8000万像素，解码时采样至最多600万像素/4096边；缩略图按需显示。每次最多4张。加密备份总上限32MB，其中媒体文件最多12MB，超限明确失败，不静默丢图。草稿和未使用的临时文件不进入聊天备份；清理保留草稿引用。媒体文件与语义在各角色间共享，角色偏好不复制图片。

## 已知限制与下一阶段

1. 动画只保留首帧；没有内置未经授权的表情包素材，需自行导入。最多一张AI表情、同角色最近30分钟三张避重，低/中/高频最少间隔30/5/2分钟。
2. 视觉仅支持现有Chat Completions兼容image_url服务；未实现各厂商独立原生协议、离线OCR或自动探测。服务不可用时保留附件并允许显式降级。
3. 真实图片与角色回复质量需用户在自己的视觉服务上验收；不会为了开发验证静默调用账户计费服务。
4. 优先下一阶段做真机选择器、图片格式/方向、后台恢复和加密备份往返；随后用用户授权的视觉服务验证真实截图/OCR/动漫/梗意及费用，再考虑动画与更大媒体备份。v17是向前迁移，旧APK不能直接读取升级后的数据库。
