# 角色生活系统1.15：实现与验证

本次在1.14.1现有Java/SQLite/WebView架构中实现，并非Kotlin重写。审查方案不再是唯一交付：运行时代码已接通前台聊天、后台恢复、日程、写作、主动消息和备份。

## 模块与数据

| 模块 | 职责 |
| --- | --- |
| LifeData | 可注入Clock的纯规则状态机，计划/实际模拟分离，因果事件、跨日目标、情绪衰减、记忆关联、慢速演化和有界整理 |
| LifeStore | character_life单角色JSON文档，SQLite事务、来源重映射、快照投影、分享提交、编辑及备份验证 |
| BehaviorPlanner | 结合用户意图、可中断性、情绪、精力、人设表达强度选择表达目标、长短及可选行为，不生成固定台词 |
| ChatEnvelope | 一次现有模型调用返回多条ja/zh气泡、事件分享引用和有限新目标提议；校验协议并兼容原文本 |
| LifeRuntime/life.js | 独立本地执行队列与生活管理页；不排在模型队列后，不调用模型读取/校正 |

SQLite v14新增character_life(character主键,revision,body)，以及messages.generated_at。body内包含enabled/evolution/eventOnlyReach、observedAt/zone、events、goals、emotion、profile、memories、influences和evolutionLog。单角色文档有长度和集合上限，数据库事务序列化写入，UI编辑使用revision，模型提议在投放时再校验版本。

事件有id/title/kind/status/origin、start/end/at、parent、goalId/goalStep、source、mentionedAt/messageRef等。所有生活事件origin为simulated_life，与用户事实、原作剧情和真实设备操作分开。外部结果必须显式确认，不依靠日程结束自动得出。

## 状态与调用流程

1. 收到消息、后台检查或打开生活页时，用统一设备时钟和角色有效时区按需推进。临时状态覆盖活动；睡眠有宽限期，持续夜聊不强制判睡。
2. 只有已开始的虚拟活动按规则完成；未开始且已错过的计划标为missed。已知事件可跨日推动目标，阶段索引防止旧结果被误用为新阶段结果。小困难在实际观察到活动中途后才成为事件，后续相关活动能留下处理来源。
3. 情绪随真实经过时间衰减，有来源的事件只影响一次；正向聊天影响按小时去重。长期可变状态要求跨日证据，每7天最多变化一次，核心人设不变。
4. 选择最多4个相关生活事件、4个生活记忆引用及当前目标，提供行为规划；原有短期对话、用户语义记忆、时间记忆及约定继续由现有模块提供。
5. 在现有聊天模型请求前附加时间和生活快照。一次返回1–3组双语气泡；主动消息最多1组。协议损坏不展示内部JSON。没有新增独立生活、情绪或行为模型请求。
6. 消息正式投放事务内更新分享、有限目标提议和情绪来源；失败/取消不提交。主动投放前再次检查事件是否有效且未分享，以及现有频率/预算/免打扰/作息限制。
7. 当天日程生成复用原调用，输入生活延续信息；日记与信件引用已记录的虚拟事件。无须全天运行模型。

generated_at是台词形成时间，sent_at是实际投放时间。两者随备份保存；后续模型上下文按形成时间理解角色早先的“今天/正在”。UI对明显延迟的内容显示形成时间，不对已生成内容偷偷收费重写。

## 使用和运行恢复

入口：设置 → 生活日常 → 角色生活状态。支持按角色暂停、关闭慢速演化、只允许事件驱动主动消息、手动记录目标、校正事件、确认外部结果和重新校准回退后的时钟。日程需由用户在原行程设置开启；新目标在后续日程生成时关联活动，不为此额外请求模型。

重启后从SQLite读取状态，不补演数小时生活。错过后台任务不会生成“已经做过”的无依据经历。设备时间回退保留不确定性，过期手动覆盖不再使用。计划时区切换不改写已经发生事件的绝对时间。

备份v14包含生活档案、配置及消息形成时间；导入时验证角色/因果无环/范围/数量，并重映射分享来源。旧版备份没有生活档案时清除旧生活状态，避免与替换的聊天混合。原有角色时区覆盖偏好仍是本机设置，尚不随备份迁移。

## 验证

原有完整离线回归覆盖聊天、语音、记忆、好感、约定、日程、写作、主动计划、数据库争用及未读。新增注入时钟测试覆盖跨日阶段、重复任务、重启、24小时以上离线、未开始活动、情绪惯性、人物差异、事件引用、协议失败、多气泡语音、睡前宽限、连续夜聊、延迟形成时间和导入来源映射。原TemporalTests继续覆盖时区、日期及夏令时。

真实SQLite测试执行生产v14建表/迁移，验证旧聊天保留、形成/投放时间、重新打开数据库、旧revision隔离、消息/生活/待回复共同回滚和重复投放隔离。它不是Android生命周期测试。

浏览器假桥接验证角色隔离、设置与校正参数、暂停、读取失败/重试、迟到结果不抢页面、深浅色窄屏、多气泡最后一段可见才确认整条消息，以及更新公告。它不是对手机WebView性能的测量。

没有读取手机密钥或私人聊天，没有调用真实模型，没有自动安装手机。真实语言质量与实际后台唤醒需要后续真机使用验收，不能用规则测试替代。Vivo桌面角标仍属既有未解决真机问题。

## 保留范围

这是有明确规则、来源和边界的虚拟生活系统，不能保证任意LLM始终遵循人设与时态。外部结果不自动猜测；结构化分享标记在旧文本模式下不可保证取得；省电和强制停止不保证准点。详细事件/目标/记忆按数量和时间有界整理，避免长期运行无限增长。人格演化目前实现兴趣积累与信心缓变，不允许改写核心身份、价值观或创造真实世界操作。
