# 角色生活连续性：源码审查与实施方案

审查基线：本地Android 1.14/code67，继续现有源码，不重新拉取、不迁移为Kotlin。1.14.1为独立公告补丁，尚未实现本方案中的新增生活模拟功能。自动日程检查保留此前确定的03:00。

## 现有链路与根本问题

| 范围 | 当前实现与可复用内容 | 需要扩展的部分 |
| --- | --- | --- |
| 聊天 | WebActivity.generatePending、ReplyFallback、ModelClient；批次收集、revision隔离、流式生成、pending_replies暂存、事务投放 | 三条最终生成路径必须读取同一生活快照；不能仅改前台提示词 |
| 输出展示 | ReplyText清理内部时间标记，WebView解析ja/zh双语；VoicePlayer/VoiceLibrary播放、缓存和保存单条语音 | 多气泡结构化协议需要双语配对、历史兼容和语音逐条播放验证；未确认已有表情包协议，不宣称已实现 |
| 身份人格 | CharacterPrompts逐角色sheet/facts版本，Hearts专属关系档案，Progression/HeartScenes关系与重要剧情 | 稳定身份与关系已有来源；没有缓慢变化且有事件依据的兴趣/习惯人格状态 |
| 时间日程 | ScheduleEngine/Store/Data/Runtime；TemporalData/Runtime即时读取角色有效时区、计划活动、进度与互动间隔 | 日程生成只提供资料/习惯，没有持续目标和前日事件输入。计划不是实际经历，当前实际状态主要unknown/手动临时记录 |
| 记忆 | Recall稳定事实检索与来源、替代关系；MemoryNotebook事件日期/状态/原文证据/修订；PromiseData约定 | 尚无角色私生活因果链、事件与情绪/目标关联；日期级记忆不足以还原日内过程 |
| 写作 | WritingEngine、LettersEngine、DiaryStore、LetterPlanStore、WritingStore事件记录及去重尝试 | 私人生活事实应从统一事件流选择，不能把日记文字直接反写为已经发生的事实 |
| 主动行为 | ReachPlans持久计划、ReachExecution请求前后复查、额度/冷却/免打扰/相似度、失败恢复 | 仍以时段、关系和间隔为主；没有消费已发生的生活事件及分享状态 |
| 后台与通知 | WorkManager、JobScheduler/Alarm入口、ReplyWorkService、系统通知、UnreadState与角标兼容 | 不能保证杀进程/省电后准点执行。恢复只能按证据和规则推进，不能补造离线经历。桌面角标仍待真机数据 |
| 持久化 | ChatStore共享SQLiteOpenHelper，WAL，事务；SQLite与加密备份v13，PersonalMerge处理并发个人资料变更 | 新增生活表需要数据库与备份成套升级；1.14的角色时区/临时设置目前不进入加密备份 |

因此问题不只是提示词：源数据缺少独立生活状态；日程生成缺少跨日输入；没有事件状态机和情绪衰减；多条生成路径和延迟投放可能读取不同时间状态。1.14已把时间快照接入最终请求，但不能凭空提供未持久化的生活经历。最终答案提前生成并等待投放，实际晚投放跨活动边界仍是待解决问题。

## 具体增量设计

### 数据结构（建议下一数据库版本，当前尚未建表）

- character_life：character主键，revision、observed_at、effective_zone、activity_event_id、emotion（类别/强度/energy/来源/observed_at）、traits、goal摘要。身份与核心价值观继续来自CharacterPrompts，不复制进此表。
- life_events：id主键，character、parent_id、kind、origin、status、start_at/end_at、next_check_at、revision、importance、source_ref、body。origin区分simulated_life、user_reported、chat_evidence，绝不表示真实设备操作已完成。
- life_steps：event_id + step_key唯一键，effective_at、applied_at、from_status、to_status、reason、source_ref；同一任务重跑不重复推进。
- life_mentions：event_id + message_id唯一，记录哪条已投放消息确实分享了哪一步；生成失败或取消不算已分享。
- memory_event_links：memory_id + event_id唯一，附来源类型、版本和证据；不能跨角色泄漏私人事件。
- 对JSON长度、字段枚举、数值范围、父事件同角色、因果无环、时间顺序、版本冲突及角色ID做验证。索引character/status/next_check_at，避免全表读取。

### 状态更新流程

1. 收到一批用户消息后由已有pending revision冻结批次；使用注入Clock得到可信设备时间与角色时区。
2. 按需推进到当前时间：只执行已保存且前置条件满足的确定性步骤；缺少结果的比赛/考试/外部事件进入awaiting_outcome，不自动编造成功失败。
3. 03:00生成计划时读取前日摘要、未解决事件和目标下一步，再复用现有ScheduleGeneration生成调用与重试策略。随机小事件由计划提出并明确标为simulation，实际开始/结果由状态机控制。
4. 读取临时覆盖、当前实际活动及计划；构建不可变快照并返回revision。后台错过多日仅推进有依据的步骤，合并历史，不逐小时调用模型。
5. 情绪按真实经过时间衰减至人格基线，再叠加有ID的事件影响；同一影响仅应用一次。未依据用户每条消息重置心情。睡眠/活动影响精力只属于虚拟模拟值。
6. 行为规划使用当前用户意图、生活状态、人格和关系，选择回答/接话/分享/观点/简短/结束等表达目标；不增加额外LLM请求，不用固定概率冷落用户。
7. 一次已有聊天调用返回兼容协议：messages（最多3组ja/zh气泡）、event_mentions、有限状态提议、memory提议。前期保留旧文本输出兼容，解析失败不得把JSON直接展示给用户。
8. 状态提议仅能引用已授权事件和允许的状态迁移；模型不能改写时钟、基础身份、用户事实或真实世界完成状态。
9. 在现有deliverPending事务内按revision校验，保存消息/分享记录/记忆链接/有效状态变更。取消、旧批次和失败不提交。发生并发冲突时保留消息并丢弃不安全提议，而非覆盖新状态。

### 主动消息与慢速人格变化

沿用ReachPlans和所有用户开关、冷却、额度、免打扰、相似度及后台限制。候选窗口绑定event_id/step_key，实际发送前后重查是否仍有未分享内容、活动是否有效；成功投放才标记分享。旧的纯时间问候可保留为明确兼容选项，不强制为凑次数生成生活事件。

长期变化只针对可变兴趣/习惯/信心，每次幅度受限、同日累计有上限；需要跨日且不同事件证据，保存变更前值及原因，允许关闭和重置。不能由几句夸奖重写角色核心人格。

### 延迟投放边界

保留due_at冻结，不重复抽延迟。生成快照增加valid_until（活动结束/临时状态过期/跨日中最近边界），投放超时不自动收费重写。先采用避免确定现在时的生成策略并展示可重生成状态；若以后选择到期才生成，必须先调整待回复状态机并测试后台限制，不能静默改变延迟功能。

## 成本、容量与隐私

本地状态推进/行为规则/情绪衰减不调用模型。每轮额外快照最多约3000字符，最多取4条相关事件、2个未完成目标、近期情绪来源；不复制整段历史。日程沿用现有日额度；记忆优先复用已有分析调用，关闭记忆时不新增隐式提取。未来结构化输出增加字段须设置长度/数量上限，记录请求数和提示长度用于离线成本回归。

活跃事件与归档分离，完成事件压缩摘要但保留ID/来源。低重要性无引用事件按保留期清理，目标/约定/锁定记忆不自动删除。只向用户配置的模型发送本轮必要上下文，源码仓库不包含个人聊天、密钥与原始运行数据。

## 分阶段实施及验收

1. 数据库迁移、生活快照、Clock和备份导入导出；验证v13升级、重启恢复、失败回滚、角色隔离、时区/夏令时。
2. 事件状态机、跨日目标、记忆关联；验证重复任务幂等、多日离线不伪造结果、父事件未完成时子事件不提前发生、纠错与去重。
3. 情绪衰减与行为规划；验证同一事件不重复叠加、时钟回退不放大情绪、连续聊天不瞬间换心情、不同人格差异及表达边界。
4. 兼容结构化单次输出、多气泡、事务提交与语音；验证批次revision、取消/重试、双语配对、记忆冲突、旧历史与语音不退化。
5. 主动事件绑定与人格慢变；验证分享去重、全局额度、用户关闭、过期重新检查、不同事件证据及慢变上限。
6. 所有原离线回归、假模型端到端、真实模型人工验收清单。未获授权前不使用手机密钥调用付费模型；假模型通过不能代表真实语言质量通过。

模型验收比较同一角色、话题、上下文在不同时间/生活/情绪输入下的最终回复：是否因果一致、无未来经历、不过度报告状态、不机械提问、不伪造现实操作。检查连续消息、24小时以上间隔、08:30/12:30/23:30/02:00和活动边界。
